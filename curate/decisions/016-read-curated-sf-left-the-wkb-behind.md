# 016 — `read_curated_sf()` decoded the geometry and kept the blob, and it broke the tag

*2026-09-22. Found by `curate/ais_ping_tag.R` failing on its first run after the
`ping_union` rebuild. Fixed the same day.*

## The failure

```
Binder Error: table "st_read" has duplicate column name "geom"
```

`curate/ais_ping_tag.R:11` opens `staging/aux/ports.fgb` through DuckDB's `st_read`.
The file carries a field literally named `geom` *and* a geometry column named
`geometry`; `st_read` maps the geometry to `geom` as well, the two collide, and the
whole stage refuses to start.

## Why the file looked like that

`R/write_curated.R:111` read back an sf object as:

```r
sf::st_as_sf(d, geometry = sf::st_as_sfc(structure(d[[gcol]], class = "WKB"), ...))
```

`st_as_sf(d, geometry = ...)` **adds** a column called `geometry`. It does not consume
the column it was decoded from, so the raw WKB blob stays exactly where it was. Every
frame returned by `read_curated_sf()` therefore had two: `geom` as a blob and
`geometry` as the geometry.

Harmless inside R — `sf` uses the active column and ignores the other. Fatal on the way
out: `reference/geo/shapes.R:73` writes that frame with `write_sf()`, which faithfully
records both, and the next reader is DuckDB.

**It also meant `read(write(x))` did not return `x`.** A round trip added a column and
renamed the geometry, which is the kind of thing that stays invisible until something
downstream is strict.

## The fix

Decode in place, under the column's original name:

```r
g <- sf::st_as_sfc(structure(d[[gcol]], class = "WKB"), EWKB = TRUE)
if (length(crs)) sf::st_crs(g) <- crs
d[[gcol]] <- g
sf::st_as_sf(d, sf_column_name = gcol)
```

`curated/reference/port_geometry.parquet` now reads back as 17,994 rows, columns
`pid, port, hid, unlocode, source, priority, geom`, `sf_column` = `geom`, CRS 4326,
all geometries valid — and the round trip is faithful.

## Blast radius

Small, and worth stating because the failure mode is silent. **One function, one
caller, one affected curated file.** `read_curated_sf()` is used in exactly one place
(`reference/geo/shapes.R:70`), and `curated/reference/port_geometry.parquet` is the
only file under `curated/` that carries `fd.geometry` at all — checked by reading the
provenance of every parquet there.

The affected outputs are `staging/aux/ports.gpkg` and `ports.fgb`, both written from
that frame. Regenerated by re-running `reference/geo/shapes.R`, the declared producer,
rather than by patching the files.

## What this says about the gate

`write_curated()` was adopted to make `curated/` self-describing, and it does that
well — the provenance stamps are what identified the single affected file in one pass.
But nothing tested that a written sf object reads back equal to itself. The defect sat
in the reader from the day it was written and surfaced only when a *different* consumer,
with a stricter parser, was handed the downstream artefact four months later.

A round-trip assertion belongs beside `write_curated()`: write a small sf object, read
it, compare names, geometry column and CRS. Not written yet.
